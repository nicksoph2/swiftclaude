Configuration Scopes

Claude Code reads configuration from six layered scopes. When the same setting appears in multiple scopes, the higher-precedence scope wins. Claude Config Manager shows you this layering so you can trace exactly where each active value comes from.

Precedence Order

Scopes are evaluated from highest to lowest precedence:

1 Managed Enterprise / MDM policies — highest priority
↓ overrides
2 User Global user config in ~/.claude
↓ overrides
3 Project Shared project config (committed to git)
↓ overrides
4 Project-Local Personal project config (not committed)
↓ overrides
5 Session Live session state (resolved/merged)
↓ overrides
6 CLI Command-line argument overrides

Managed Scope

The Managed scope contains enterprise-level policies that cannot be overridden by lower scopes. These come from three possible tiers:

  • Server-managed — policies pushed from a central server
  • MDM — macOS Mobile Device Management profile domains
  • File-based — a managed settings.json at a system path

The active tier is shown in the Managed scope view. If no managed configuration is detected, this scope appears inactive.

User Scope

Your global Claude configuration lives at ~/.claude (or a custom path you've authorised). This scope typically contains:

  • settings.json — global settings like default model, theme, API keys
  • CLAUDE.md — global instructions appended to every session
  • .claude.json — MCP servers and agent definitions

You can change which folder the app reads by clicking Choose Different Folder in the User scope view or in Settings → Global Root.

Project Scope

Project configuration lives in the root of a project directory. These files are typically committed to version control so your entire team shares the same Claude Code setup:

  • .claude/settings.json — project-level settings
  • CLAUDE.md — project-specific instructions
  • .claude.json — project MCP servers

Project-Local Scope

Project-Local files are personal overrides that live alongside project config but are not committed. They use .local variants:

  • .claude/settings.local.json
  • CLAUDE.local.md

Use these for personal preferences that shouldn't affect teammates.

Session Scope

The Session scope shows the live merged state during an active Claude Code session. It includes the final resolved settings, merged instructions, active hooks, and MCP server connections.

CLI Scope

Command-line arguments passed when launching Claude Code (e.g., --model) act as the lowest-precedence overrides. This scope is placeholder when no CLI session is active.

Note: The sidebar shows a colour dot next to each scope and a badge with the number of discovered files. Scopes with no files display as "inactive".
